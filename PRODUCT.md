# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- **Primary:** a solo product builder (the kit's owner) who guides an AI agent through PRD → plan → build → verify → archive. Opens the pages between builds, on a desktop, to see what a product does, why, and what's still undecided.
- **Secondary:** people the builder shares a project's docs page with (collaborators, testers) who need to understand the product's behavior without knowing the kit or OpenSpec.

## Product Purpose

ac-workbench is a personal Claude Code kit (plugin `kit`). Its visual surfaces are generated, read-only pages:
- the **docs page** (`/kit:docs`, M8): one per project, built from the project's specs, archived changes, decision records and curated notes;
- the **cockpit** (M5, later): an overview of projects, tools and lanes.

Success for the docs page: a reader finds a behavior and its reason fast, and can't miss what is undecided.

## Positioning

The docs are rebuilt from the project's own planning record (OpenSpec specs and archived changes) at each archive, so they describe what was actually built, with Given/When/Then behaviors, and the "why" only where a decision has depth.

## Operating Context

- Generated by a zero-dependency Node script into one static HTML file, committed in the project (`knowledge/docs/index.html`), opened locally from disk.
- Content is user-centric: behaviors, how it works roughly, reasons, foundation cards, a tools inventory, history per sub-feature, open decisions.

## Capabilities and Constraints

- One self-contained file: inline CSS and JS, no web fonts, no CDN, no network requests.
- Light and dark (`prefers-color-scheme`).
- Must stay readable with 1 or 100 sub-features and long scenario text.
- The same sources must produce a byte-identical page (no timestamps).
- Source text is untrusted: everything escaped.
- The look should be reusable by the M5 cockpit page later.

## Evidence on Hand

- Real content: this repo's 11 specs and 6 archived changes; the Toughbubble copy's Storms specs (`Projects/temp/Toughbubble`).
- No testimonials, users or metrics exist; none may be invented.

## Product Principles

1. Find a behavior and its reason fast.
2. Undecided things are impossible to miss.
3. Plain language for someone who doesn't know OpenSpec; technical detail only where it changes what the product can do.
4. Rebuilt, never hand-edited: the page is a view of the record.
